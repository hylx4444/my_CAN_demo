# 真实硬件联调记录

## 已确认的结果

2026-10-28，用户报告真实传感器数据已经显示在网页上，改变传感器温湿度后，页面显示也随之变化。

本次确认的链路为：传感器厂家自定义 CAN → LAUNCHXL-F2800157 → UART → WEMOS S2 Mini → Wi-Fi 热点 → 手机网页。

## 当前版本与连接

- S2 Mini 固件标识：`s2-diag-1`，真实串口模式，GPIO5 为接收输入，GPIO4 预留并保持输入，不连接反向发送线。
- 两板数据线：157 的 J1 第 4 脚 GPIO29 / SCIA_TX → S2 Mini GPIO5 / UART1_RX。
- 两板地线：157 主控侧 GND → S2 Mini GND；排针以实物丝印确认。
- 157 的 S2 / UART Select：SEL1=1、SEL2=0；S3 / BOOT：1/1，从 Flash 启动。
- CAN 接收配置：100 kbit/s、29 位扩展数据帧、ID `0x18FF0000`、DLC 8、默认地址 1；传感器按线标签接 J14 CANH/CANL，S4 选择 XCVR。
- 网页地址：`http://192.168.4.1`；热点 CANopen-Demo，密码 can-demo-123。

供电调试建议两板各自使用 USB，板间只连接信号与共地，不互接 5V/3V3。外置电源接法与长期供电稳定性没有单独完成验证记录。

## 此次固件和工具调整

真实串口模式不再驱动未使用的 GPIO4 发送脚；UART 接收任务周期性让出 CPU，并统计原始字节、帧错误、奇偶校验错误、BREAK、缓冲溢出和读取错误。USB 日志每两秒输出启动阶段和接收计数，Wi-Fi 事件记录热点启动/停止。

`/api/status` 保持原遥测字段，另增加以下诊断字段：

| 字段 | 含义 |
| --- | --- |
| firmware | 当前固件标识 |
| esp_uptime_ms | S2 Mini 自身运行时间；旧字段 uptime_ms 仍属于 157 |
| boot_phase | 启动阶段，6 表示 HTTP 服务就绪 |
| ap_running | Wi-Fi 驱动是否报告热点正在运行 |
| uart_rx_bytes | 累计接收的原始串口字节数，不要求是合法遥测 |
| uart_frame_errors / uart_parity_errors | UART 硬件帧错误 / 奇偶校验错误事件数 |
| uart_overflows / uart_breaks / uart_read_errors | 缓冲溢出 / BREAK / 读取错误次数 |
| received_frames | 成功解码的遥测帧数 |

`tools/monitor_esp32s2.py` 支持 USB 重新枚举后重连，单设备模式可跟随下载/运行模式身份变化。根据本机 ESP-IDF USB 控制台实现，DTR=1 时的 RTS 下降沿可能请求进入下载模式；工具已修改控制线设置，关闭串口仍可能触发普通复位。核对正常启动表现时应关闭监听后再断电启动。

## 烧录过程中的观察

用户最终通过 ESP-IDF 成功烧录。Windows 原生 USB 自动复位曾出现连接失败，因此不能只按固定 COM 号判断启动模式；端口必须重新查询。此次设备在运行模式显示 COM6 和 MAC 序列号，手动下载模式曾显示 COM5、序列号 0，这只是本机观察，其他电脑的 COM 号可能不同。

`flash_prebuilt_esp32s2.ps1 -DownloadMode` 只跳过烧录前自动复位，不会自动进入下载模式。固件仍运行时使用该参数，可能一直等待下载握手。原生 USB 没有枚举时，换用 IDF 也不能绕过端口问题。

正常和本地模拟应用已重新编译、打包，预编译应用与当前构建文件 SHA256 一致。源代码中文文件说明及函数注释已检查；串口监视工具的重连、身份变化及控制线设置已使用模拟设备测试。

长时间运行、断线恢复、整机断电重启、温湿度精度校准与现场干扰测试未单独记录。传感器超时、负温度等已有软件测试覆盖，不等同于真实硬件环境逐项实测。
